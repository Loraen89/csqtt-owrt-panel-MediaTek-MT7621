# LuCI-панель CSQTT 2.0-r4

Версия `2.0-r4` исправляет две ошибки совместимости выбранного ядра 2.1.9.

## Исправления

- RPC-методы импорта `csqtt://` и проверки VK-хешей используют бинарник,
  выбранный параметром `csqtt.main.core_version`, вместо отсутствующего
  устаревшего пути `/usr/bin/csqtt-core`.
- Общий procd init-скрипт больше не передаёт ядру 2.1.9 параметры,
  появившиеся только в 2.5.1 (`runtime-threads`, `srtp-mode` и параметры
  расширенной маршрутизации).
- Для 2.1.9 пароль подключения передаётся обязательным CLI-параметром;
  2.5.1 продолжает получать его через `CSQTT_PASSWORD`.
- Версия пакета панели повышена до `2.0-r4`.

## Проверка на Netis N6 v1

Проверено на реальном Netis N6 v1 с OpenWrt 25.12.5:

- оба ядра установлены, выбрано `core_version=2.1.9`;
- сервис запускается без циклических перезапусков procd;
- 27 воркеров переходят в состояние `READY`;
- интерфейс `csqtt0` получает IPv4-адрес;
- RPC `hashes_validate` возвращает `ok=true`, все три проверенных хеша
  имеют состояние `valid`;
- LAN-доступ к LuCI и отдельный интернет-доступ тестового ПК через Wi-Fi
  сохраняются;
- LTE-интерфейс `wwan0` проходит ICMP и DNS. Отказ HTTPS через LTE связан
  с известным ограничением мобильного оператора, а не с пакетом.

Секреты профиля, ссылки и значения хешей в репозиторий и логи релиза не
добавлялись.
