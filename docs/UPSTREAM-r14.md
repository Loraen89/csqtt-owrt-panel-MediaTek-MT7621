## Поставка 2.5.3

Использован официальный файл выпуска `v2.5.3`:

`csqtt-core-2.5.3-openwrt-24.10.8-ramips-mt7621-mipsel_24kc.ipk`

SHA-256 исходного пакета:

`e40b69b393b0d9a4b8a42e3184d08c7e02da6ca1eeab8cb5815ebdbbf08d022b`

| Компонент | SHA-256 |
|---|---|
| transport `/usr/bin/csqtt-2.5.3` | `c3a816842579583ad83bb7f38b08a2b266e54a4ee3b3dd21246d778328c80a7d` |
| supervisor `csqtt-control` | `4e40dd75c3ddf5e53577fd808dcd07cf96a22471172238a1dc98babc892e1e1e` |

`tools/prepare-cores.mjs` скачивает именно этот файл, проверяет фиксированную
сумму и извлекает только транспорт, supervisor и лицензии. Путь к уже скачанному
пакету можно передать первым аргументом. Из пакетов текущего `dist/` этот скрипт
также восстанавливает бинарники 2.1.9 и 2.5.1 с проверкой SHA256SUMS.

```sh
node tools/prepare-cores.mjs
node luci-app-csqtt/build-package.mjs
node tools/verify-panel.mjs
```

Исходный пакет имеет ревизию 2.5.3-r10; локальная переупаковка — 2.5.3-r11.
Исполняемые файлы остаются неизменными. Supervisor устанавливается в приватный
путь `/usr/libexec/csqtt/csqtt-control-2.5.3`. Активационные скрипты upstream,
его init и UCI-шаблон не устанавливаются: они заменили бы общий управляющий
слой и нарушили совместное использование трёх ядер.

В отличие от статических 2.1.9/2.5.1, транспорт 2.5.3 для MIPS динамический.
В пакетах объявлены зависимости `libc`, `libgcc1`, `kmod-tun`. Сборка пакета
для 25.12 использует те же бинарники; совместимость с конкретными библиотеками
роутера должна быть подтверждена аппаратным испытанием.

Лицензии и NOTICE ядра и Gooby сохраняются в пакете. Полный upstream-исходник
и OpenWrt-патчи 2.5.3 в публичном дереве starkugz не представлены;
эта адаптация не заявляет собственную пересборку или воспроизводимость
компиляции этого ядра. Воспроизводимость локальной упаковки проверяется отдельно.

## Запуск и совместимость

| UCI core_version | Запуск |
|---|---|
| `2.1.9` | Только прежний core 2.1.9, legacy CLI |
| `2.5.0` / `2.5.1` | Только прежний core 2.5.1, пароль через окружение |
| `2.5.3` | Только supervisor 2.5.3 и внешний транспорт с TUN-сокетом |
| `auto` | Установленный 2.5.3, затем 2.5.1, затем 2.1.9 |

Ссылка не кодирует надёжно версию wire-протокола; при импорте ядро выбирается
явно. Открытые и зашифрованные ссылки используются разными поколениями клиентов.
Старые профили с `core_version=2.5.0` не переназначаются на 2.5.3.

Для 2.5.3 `run-253.sh` создаёт root-only UCI-снимок в tmpfs, переносит
общие значения только в пустые поля выбранного профиля, отключает остальные
профили и failover/failback. Основной конфиг не меняется. При завершении snapshot
удаляется. Поэтому supervisor не может сам переключить протокол на соседний
профиль. Для смены ядра нужна смена профиля и перезапуск единственной службы.

Встроенный Gooby передаётся как `gooby_mode=embedded`, только для 2.5.3 и TCP/TLS.
Поддержка сторонних Gooby proxy/ZIP-стратегий этим изменением не добавляется.

## Проверки и пределы

Локально проверяются:

```sh
node tools/test-compat.mjs
node tools/test-profile-edit.mjs
node tools/test-253-wrapper.mjs
sh tools/test-core-selection.sh .
node tools/test-export.mjs
node tools/test-logs.mjs
node tools/test-backup.mjs
node tools/verify-panel.mjs
node tools/test-reproducible.mjs
```

`tools/test-rpc.mjs` формирует из действующей реализации RPC регрессии для ucode:

```sh
node tools/test-rpc.mjs /tmp/csqtt-rpc-regression.uc
ucode /tmp/csqtt-rpc-regression.uc
```

Нативный ucode, LuCI в браузере, физический MT7621 и QEMU для r14 не запускались.
Реальный туннель, передача трафика, Gooby, CAPTCHA, Flood control и восстановление
после сетевых сбоев новой сборки не проверены. Локальные тесты команд и моков
не подтверждают работу этих сценариев на роутере.
