# LuCI-панель CSQTT 2.0-r2

Версия `2.0-r2` переносит проверенную на Netis N6 функцию диагностики
HTTPS-доступа в общую панель MediaTek MT7621. Поддержка ядер 2.1.9 и 2.5.1,
выбор ядра и существующая схема пакетов сохранены.

## Изменения

- добавлен выбор OpenWrt, GitHub, Cloudflare или Google на странице состояния;
- RPCD выполняет `curl` с привязкой к активному TUN-интерфейсу `csqtt0`;
- запрос ограничен по времени и проверяет HTTP-коды `2xx`/`3xx`;
- результат сохраняется в `/var/run/csqtt/access-check.json` не более чем на
  пять минут и привязывается к интерфейсу и текущей сессии;
- в «Подробностях» отображаются цель, время, HTTP-код и причина результата;
- секция «Подробности» раскрывается при открытии страницы;
- установка панели перезапускает только RPCD и не прерывает процесс CSQTT.

Проверка не меняет UCI, маршруты, firewall, системный DNS, LAN/WAN/Wi-Fi или
конфигурацию SSClash и не является фоновым мониторингом.

## Проверка на Netis N6

На физическом Netis N6 v1 с OpenWrt 25.12.5 проверка через `csqtt0` вернула:

| Цель | HTTP-код |
|---|---:|
| OpenWrt | 200 |
| GitHub | 200 |
| Cloudflare | 200 |
| Google | 204 |

После установки процесса CSQTT сохранил прежний PID; DNS, обычный HTTPS и
HTTPS через `csqtt0` продолжили работать. Перезагрузка маршрутизатора не
потребовалась.

## Локальная проверка в QEMU для Netis N6 v1

Итоговые APK дополнительно установлены в OpenWrt 25.12.5 для MIPS Malta с
процессором 24Kc — той же целевой ISA `mipsel_24kc`, что используется Netis
N6 v1. Тест выполнялся на отдельной копии диска QEMU; исходный образ не
изменялся.

Проверено:

- SHA256 всех трёх APK внутри гостевой системы совпадает с `dist/SHA256SUMS`;
- `ucode -c` успешно компилирует RPCD-обработчик;
- UBUS регистрирует `csqtt.status` и `csqtt.access_check`;
- без поднятого `csqtt0` ручная проверка безопасно возвращает
  `tunnel interface is not ready`;
- ACL новой LuCI-сессии разрешает чтение и запись UCI-конфигурации `csqtt`;
- в браузере страница состояния открывается без ошибок консоли, выбирает
  OpenWrt по умолчанию, раскрывает «Подробности» и показывает ядро
  `csqtt-client 2.5.1-mt7621-r1`;
- контрольные суммы `/etc/config/network`, `/etc/config/dhcp` и
  `/etc/config/firewall` после установки не изменились.

QEMU подтверждает совместимость пакета, RPCD/UBUS и интерфейса LuCI с целевой
архитектурой. Malta не эмулирует SoC и периферию MT7621/Netis N6, поэтому
радиомодуль, аппаратное ускорение и реальный модем этим тестом не покрываются.

## Безопасное точечное развёртывание

Сценарий `docs/diagnostics/deploy-access-check-guard.ps1` резервирует
затрагиваемые файлы и `/etc/config/csqtt`, устанавливает RPC/UI без перезапуска
CSQTT и проверяет DNS, обычный HTTPS, HTTPS через `csqtt0`, CSQTT, SSClash и
TUN-интерфейс.

Адрес маршрутизатора и файл `known_hosts` передаются обязательными параметрами.
При неудаче сценарий выполняет откат без перезагрузки. Перезагрузка после
отката возможна только с явным параметром `-RebootAfterRollback`.

```powershell
powershell -ExecutionPolicy Bypass -File .\docs\diagnostics\deploy-access-check-guard.ps1 `
  -Router 'router.example.lan' -KnownHosts '.\router-known-hosts'
```
