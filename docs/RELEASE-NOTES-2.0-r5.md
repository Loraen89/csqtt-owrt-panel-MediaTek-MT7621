# LuCI-панель CSQTT 2.0-r5

Версия `2.0-r5` локально интегрирует визуальные компоненты официальной
панели [`starkugz/csqtt-openwrt`](https://github.com/starkugz/csqtt-openwrt)
2.0 в пакет для MediaTek MT7621. Публикация этой сборки не выполнялась.

## Что изменено

- Добавлены официальные модули темы, обработки `csqtt://`-ссылок и токена VK.
- Все существующие страницы MT7621-панели используют общую адаптивную тему,
  при этом сохранены совместимые RPC, init-скрипт и схема UCI v2.
- Импорт открытой ссылки `csqtt://connect?...` после проверки endpoint,
  порта и пароля устанавливает для нового профиля `core_version=2.1.9`.
- Зашифрованная ссылка расшифровывается только ядром 2.5.0/2.5.1; после
  успешной аутентификации ссылки и проверки обязательных полей выбирается
  профильное `core_version=2.5.0`.
- Предпросмотр и ошибочные ссылки не меняют конфигурацию. Выбор ядра
  сохраняется только вместе с успешным импортом профиля.
- Карточка каждого профиля показывает назначенное ядро; то же поле доступно
  в редакторе профиля. При ручном выборе и автоматическом переключении init
  запускает ядро выбранного профиля, а глобальное значение остаётся fallback
  для старых конфигураций без профильного `core_version`.
- Добавлен RPC `link_decrypt`, совместимый с официальным модулем панели для
  работы по обычному HTTP, где WebCrypto недоступен.

## Почему backend не заменён целиком

Официальная панель использует отдельный управляющий бинарник `/usr/bin/csqtt`
и схему профилей v3. Этот MT7621-пакет запускает два исходных MIPS-ядра
напрямую и использует проверенный init/RPC-слой схемы v2. Полная замена
официальным RPC сделала бы пакет неработоспособным, поэтому перенесён UI-слой,
а обработка ссылок адаптирована к двум локальным ядрам.

## Локальная проверка

- SHA256 официального APK панели 2.0 сверялся с опубликованным `SHA256SUMS`.
- Официальный APK установлен в одноразовой QEMU OpenWrt 25.12.5 MIPS-среде и
  его файлы извлечены для сравнения.
- JavaScript, JSON, shell и ucode проходят синтаксическую проверку.
- Локально собранный APK устанавливается в QEMU; проверяются регистрация RPC,
  загрузка LuCI и отсутствие изменения ядра на неверной ссылке.

## Проверка на реальном Netis N6 v1

9 ноября 2026 года локальная сборка `2.0-r5` установлена поверх `2.0-r4` на
Netis N6 v1 с OpenWrt 25.12.5. Перед установкой сохранена отдельная резервная
копия конфигурации, init/RPC и файлов LuCI. Контрольная сумма `/etc/config/csqtt`
до установки, после установки и после всех тестов совпала.

- Рабочий профиль сохранился и отображает ядро `2.1.9` в карточке.
- После мягкого перезапуска службы восстановились 36 из 36 рабочих каналов;
  интерфейс `csqtt0` поднят, переподключений не зарегистрировано.
- Сохранённые VK-данные прошли проверку: `3/3 valid`.
- Оба установленных ядра прошли встроенный офлайн-самотест.
- RPC-предпросмотр выбрал `2.1.9` для открытой ссылки, `2.5.0` для
  зашифрованной и отклонил ссылку без пароля, не меняя UCI.
- Страницы статуса, профилей и настроек туннеля проверены через браузер.
- DNS и ICMP через мобильное подключение работают. Прямой HTTPS остаётся
  заблокирован оператором — это известное внешнее ограничение, поэтому
  сетевые настройки не менялись.

Реальный роутер, GitHub Release и ветки удалённого репозитория в этих тестах
не изменяются. Секреты, рабочие ссылки и значения хешей не сохраняются.
