# Ядро 2.5.3 и VK Flood control

**До публикации релиза обязательна обкатка на физическом MT7621.** PR остаётся
черновиком до завершения проверки. `tools/router-smoke.sh` собирает сведения
о прошивке, архитектуре, памяти, месте и пакетах без изменения службы и без
вывода паролей. Далее проверяются установка и откат, Stop/Start, трафик,
переключение старых ядер, Device ID и пауза Flood с тестовым маркером.
Для проверки автомата не нужно искусственно вызывать ограничения VK:
`tools/test-flood.sh` использует временный каталог и тестовый контроллер.

Панель **2.0-r13** сохраняет поддержку локальных ядер 2.1.9 и 2.5.1 и
добавляет официальный транспорт **2.5.3** из `starkugz/csqtt-openwrt`, выпуск
`v2.5.3`. Исходники транспорта 2.5.3 upstream не публикует; он устанавливается
готовым пакетом вместе с контроллером. Старые исходники в `core219/` и
`core251/` остаются самостоятельными сборками, их версии не подменяются.

## Совместимость

| OpenWrt | Пакет нового ядра | Архитектура |
|---|---|---|
| 24.10.x | `csqtt-core-2.5.3-openwrt-24.10.8-ramips-mt7621-mipsel_24kc.ipk` | `mipsel_24kc` |
| 25.12.x | `csqtt-core-2.5.3-openwrt-25.12.5-ramips-mt7621-mipsel_24kc.apk` | `mipsel_24kc` |

Пакет выбирается по линии OpenWrt, архитектуре и ведомости SHA-256 выпуска.
Для SNAPSHOT MT7621 в этом выпуске подходящего пакета нет. На MIPS новый
транспорт использует musl/libgcc1 из OpenWrt; прежние ядра были статическими.
Upstream оценивает место для нового ядра и своей панели примерно в 27 МиБ
при первой установке и 51 МиБ при обновлении. Установщик проверяет место и
зависимости; подходящий `kmod-tun` должен быть доступен для прошивки роутера.

## Обновление с сохранением CSQTT-PANEL

Сначала установите панель r13 из этой ветки/подготовленного выпуска. Команды
ниже для `main` предназначены для использования **после объединения изменений**.
До объединения вместо `main` используйте имя ветки с r13.

```sh
cp -p /etc/config/csqtt /root/csqtt-before-253.backup
curl -fsSL -o /tmp/install-from-github.sh \
  https://raw.githubusercontent.com/Loraen89/csqtt-owrt-panel-MediaTek-MT7621/main/install-from-github.sh
ash /tmp/install-from-github.sh --panel-only --ref main

curl -fsSL -o /tmp/install-253.sh \
  https://raw.githubusercontent.com/Loraen89/csqtt-owrt-panel-MediaTek-MT7621/main/install.sh
ash /tmp/install-253.sh check --set core
ash /tmp/install-253.sh install --set core --dry-run
ash /tmp/install-253.sh install --set core
```

В LuCI откройте профиль, выберите **2.5.3**, задайте 10–100 воркеров, кратно
10 (пустое поле использует 10 для нового ядра), сохраните и запустите службу.
Существующие явные настройки ядра 2.1.9/2.5.1 не переписываются.
При обновлении только ядра наша панель сохраняет свой dispatcher и оставляет
ручной запуск выбранного профиля пользователю. Ключи `--set panel`/`--set both`
у `install.sh` устанавливают **панель upstream 2.5**: для сохранения нашей
панели и описанного ниже автомата Flood используйте **`--set core`**.

```sh
sh /tmp/install-253.sh install --set core --core-version 2.5.3 --dry-run
sh /tmp/install-253.sh install --set core --core-version 2.5.3
```

Новый установщик закреплён на конкретном upstream-коммите и проверяется по
встроенному SHA-256 до запуска. Пакеты проверяются по `SHA256SUMS` выпуска.
При установке только ядра он восстанавливает диспетчер CSQTT-PANEL r13 после
активации upstream-пакета. Профили и выбранные в них старые ядра сохраняются;
службу после обновления запустите из LuCI. Для перехода конкретного профиля
выберите в его редакторе **2.5.3** и **10–100 воркеров, кратно 10**.
Device ID старых профилей не изменяется; транспорт 2.5.3 его не использует.
Ссылки 2.5.3 распознаются по параметру `core=2.5.3`, в том числе после расшифровки.
Ссылки без такого параметра сохраняют прежнее определение ядра.

`--set panel` и `--set both` устанавливают **официальную панель upstream 2.5**.
Её возможности и политика Flood отличаются от CSQTT-PANEL r13. Для сохранения
этой панели и описанного ниже автовосстановления используйте `--set core`.
Последующие обновления/удаление нового ядра также выполняйте через `install.sh`,
чтобы восстановить диспетчер панели после операции с upstream-пакетом.

## VK Flood control

Транспорт 2.5.3 записывает терминальную блокировку VK (структурированная ошибка
**9**) в `/var/run/csqtt/flood-blocked`. Обёртка панели останавливает контроллер
при появлении маркера. Строки с похожими словами в журнале не снимают блокировку.

В **Настройки → VK Flood control** доступны:

| UCI в `csqtt.main` | По умолчанию | Поведение |
|---|---|---|
| `flood_auto_clear` | `1` | Автоматически снять локальный маркер после паузы и повторить подключение |
| `flood_retry_delay` | `3600` | Первая пауза в секундах, диапазон 60–86400 |
| `flood_retry_limit` | `3` | Число автоматических попыток, диапазон 1–10 |

При повторном Flood пауза удваивается: по умолчанию **1 час → 2 часа → 4 часа**,
максимум 24 часа на одну паузу. Изменение маркера начинает ожидание заново.
Таймер использует время работы системы, поэтому перевод часов не сокращает
паузу. Лимит сохраняется при respawn procd и ручном перезапуске службы в рамках
текущей загрузки. После 15 минут живого подключения бюджет обнуляется.
После перезагрузки роутера временные файлы и бюджет в `/var/run` исчезают.

На странице статуса показаны оставшаяся пауза и следующая попытка. Кнопка
**«Снять Flood и остановить»** снимает локальную блокировку и оставляет службу
остановленной. То же по SSH:

```sh
/etc/init.d/csqtt clear_flood
```

Удаление локального маркера не снимает ограничение на стороне VK. Если лимит
там ещё действует, новая попытка снова блокируется. При исчерпании попыток
автоматические подключения прекращаются до ручного решения. Остановка службы
останавливает и таймер; скрытого задания cron нет. Этот механизм относится к
**2.5.3**, поскольку старые локальные ядра не имеют такого контракта маркера.

## Проверки и ограничения

Автоматические проверки покрывают выбор/аргументы контроллера, сохранность
исходного UCI, worker rules, задержку Flood, изменение маркера, удвоение паузы,
лимит и его сохранение при respawn, отключение автоматики и остановку службы.
Собраны APK/IPK панели; проверены структура, контрольные суммы и экспорт ссылок.
Работа ядра 2.5.3, реальный VK Flood и пропускная способность на MT7621 в этой
среде не проверены. Перед использованием на основном роутере нужна приёмка
на устройстве, включая Stop/Start, оба ядра, Device ID и реальный трафик.
