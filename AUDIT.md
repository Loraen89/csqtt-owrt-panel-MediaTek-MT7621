# Проверка r9 и кандидат r10-rc1

База проверки: тег `v2.0-mt7621-r9`, коммит `8333e7e`.
Кандидат: `v2.0-mt7621-r10-rc1`, пакет панели `2.0-r10`.
Аудит выполнялся в приватном репозитории. После отдельной проверки 2026-11-10 репозиторий подготовлен к публичному размещению; стабильный Latest остаётся на r9.

## Найдено и исправлено

| Приоритет | Ошибка r9 | Исправление |
|---|---|---|
| P1 | Экспорт не учитывал ядро профиля: UI шифровал даже профиль 2.1.9, а RPC не сообщал протокол | RPC возвращает ядро и подходящий формат; 2.1.9 экспортируется открыто, 2.5.1 — через общий модуль шифрования |
| P1 | Диагностический JSON включал адреса и имена профилей через полный вложенный статус, несмотря на обещание их скрывать | Диагностика строится по списку разрешённых полей; имена/ID профилей, endpoint и сырые журналы не включаются |
| P1 | После перезапуска могли оставаться старые признаки установленной сессии и успешной проверки доступа | Обёртка очищает runtime-статус, результат проверки и замер CPU перед каждым запуском/respawn |
| P2 | Init выбирал неполный ручной профиль, а RPC выбирал запасной | Init и RPC пропускают профиль без endpoint или пароля |
| P2 | Для auto_js статус требовал ручной VK-хеш; адрес туннеля брался из необязательной настройки и оставался пустым | Статус учитывает токен auto_js и читает фактический IPv4 интерфейса |
| P2 | Сообщения `run-core.sh` терялись при отборе syslog; альтернативы шаблонов logread не работали как ожидалось | Отбор ограниченного объёма syslog выполняется в ucode |
| P2 | Категория «Ошибки» и подсветка принимали префикс `daemon.err` за ошибку даже у обычной статистики ядра | Для `run-core.sh` категория определяется по содержимому сообщения; реальные ошибки и таймауты остаются в категории ошибок |
| P2 | Локальная установка могла продолжаться без SHA256SUMS, удаление скрывало ошибки apk, обновление включало ранее отключённый автозапуск | Проверка контрольных сумм обязательна; удаляются только установленные пакеты, ошибки не скрываются; post-upgrade сохраняет автозапуск |
| P2 | Результат упаковки зависел от LF/CRLF в JS/JSON/ucode; лицензии не входили в APK | Текст нормализуется при сборке, LICENSE и NOTICE включены в каждый пакет |

Временный каталог онлайн-установщика также создаётся через `mktemp`, а не по предсказуемому PID.

## Проверки

- `node tools/test-export.mjs`: открытый экспорт 2.1.9 по HTTP, зашифрованный round-trip 2.5.1, понятная ошибка без WebCrypto.
- `node tools/test-logs.mjs`: обычная статистика и успешный TURN refresh не считаются ошибками только из-за stderr-префикса; реальные ошибки сохраняются.
- `node tools/test-rpc.mjs /tmp/test-rpc.uc` и запуск результата через ucode: credentials, адрес интерфейса, протокол экспорта, импорт, приватность диагностики, журналы, выбор профиля, CPU/RSS.
- На исходном r9 тот же набор воспроизводит ошибку `auto_js token is a configured credential`.
- `sh tools/test-shell.sh <project>` на OpenWrt, в изолированной временной папке с подменёнными apk/uci: выбор ядра, очистка старой сессии, контрольные суммы, dry-run, удаление и отказ удаления без потери конфигурации.
- `node tools/test-reproducible.mjs`: все три APK побайтно одинаковы при LF и CRLF исходниках.
- `node tools/verify-panel.mjs`: gzip/tar, arch, datahash, контрольные суммы, лицензии, неизменность бинарников ядер и отсутствие принудительного enable в post-upgrade.
- JavaScript проверен `node --check`; RPC компилируется штатным ucode.
- Зашифрованная тестовая ссылка расшифрована настоящим бинарником 2.5.1 на MT7621. Самотесты обоих ядер проходят.

## Проверка установленного кандидата

Кандидат установлен на Xiaomi Mi Router 3G / OpenWrt 25.12.5 с сохранением текущих настроек.
Контрольные суммы всех активных файлов `/etc/config` и конфигурации SSClash совпали с исходными.
Служебный шаблон `csqtt.apk-new` ожидаемо обновился. Состояние автозапуска сохранено.
После перезапуска: ядро 2.1.9, UDP, 18 активных воркеров, CPU/RSS и фактический IPv4 доступны.
Страницы «Статус», «Профили», «Туннель и VK», «Журналы» доступны с HTTP 200 после входа.
Проверка HTTPS через туннель вернула HTTP 200. Диагностический JSON проверен на отсутствие
сырых журналов и вложенных профилей с endpoint.

## Ограничения проверки

Это проверка интеграции панели и упаковки, а не полный аудит криптографии и Rust-зависимостей.
Бинарники ядер не пересобирались и не менялись; добавлены только файлы лицензий в их APK.
Экспорт 2.5.1 требует WebCrypto и защищённого контекста браузера; по обычному HTTP показывается объяснение ограничения.
Новый длительный нагрузочный тест не запускался.
Исходный syslog по-прежнему помечает stderr ядра как `daemon.err`; изменена классификация в панели, а не бинарник ядра или исходный журнал.

Graphify использован как вспомогательная карта r9: 5 371 узел, 12 075 связей, 223 сообщества.
Проверка графа выявила 1 150 связей с отсутствующими исходными узлами, одну петлю и
407 групп связей, объединённых недиректным представлением. Поэтому граф не считается
полным доказательством корректности; ucode/shell проверены отдельно. Семантическое
извлечение прочитало все пять документов полностью. Учёт токенов инструмент не предоставил.

## Поддержка OpenWrt 24.10 (2.0-r11, локальная ветка feature/openwrt-24.10)

- Добавлен второй целевой релиз: OpenWrt 24.10.x с пакетным менеджером `opkg` и форматом `ipk`. APK-набор 25.12.x не изменяется; байт-в-байт совпадение пересобранных APK с релизом r10-rc1 подтверждено контрольными суммами.
- `build-package.mjs` собирает шесть пакетов: три APK и три IPK (ar + control.tar.gz + data.tar.gz). IPK панели: `Architecture: all`, conffile `/etc/config/csqtt`, `postinst`/`prerm`/`postrm` повторяют APK-lifecycle: enable при новой установке, сохранение автозапуска при обновлении через `/var/run/csqtt-autostart-flag`, остановка службы в `prerm`, очистка `/tmp/luci-indexcache*` и перезапуск `rpcd`.
- Установщики `install-csqtt.sh`, `install-from-github.sh`, `uninstall-csqtt.sh` детектируют `apk`/`opkg` и выбирают имена пакетов соответственно. Перед установкой на 24.10.x рекомендуется `opkg update`; при недоступности фидов установка прерывается с подсказкой.
- ucode-rpcd плагин и LuCI-вьюхи используют только API, присутствующие в OpenWrt 24.10 (стандартный ucode 2022+ и LuCI client-side); несовместимостей не выявлено. Зависимости `rpcd-mod-ucode`, `ucode-mod-fs`, `ucode-mod-uci`, `kmod-tun`, `curl` — из штатных фидов 24.10.
- Проверки: `tools/verify-panel.mjs` расширен разбором IPK (ar-структура, control-поля, conffiles, lifecycle-скрипты, лицензии, совпадение ELF ядер); `tools/test-reproducible.mjs` покрывает все шесть пакетов; сценарии `tools/test-shell.sh` дополнены opkg-веткой.
- Ограничения 24.10.x: при обновлении пакета новые значения по умолчанию `/etc/config/csqtt` opkg поверх существующего файла не подставляет — новые опции задаются вручную; установка и работа на устройстве с 24.10.x ещё не проверены (пункты для проверки — `docs/openwrt-24.10.md`).
- Изменения локальные: ветка `feature/openwrt-24.10` в локальном клоне, публикация не выполнялась.
